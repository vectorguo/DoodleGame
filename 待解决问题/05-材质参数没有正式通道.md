# 05 材质参数没有正式通道

类别：结构 ｜ 优先级：中 ｜ 建议时机：独立；树叶阴影要用材质参数时提前到阴影之前 ｜ 关联：02、12

## 现状

- 材质只有一个数值参数：`DoodleMaterial` 的基色。它不走材质自己的资源，而是在 `DoodleForwardPass::Render` 里，每个绘制项做一次 `SRGBToLinear` 后写进 `DoodleForwardPassPushConstants::baseColor` —— 这是前向 pass 的 push constant 契约（`DoodlePassShaderInterface` 里 forward 的 `pushConstantRange`）。
- 材质契约（`DoodleMaterialShaderInterface.h`，由 `DoodleShader::ValidateMaterialBindings` 核对）规定 set 1 只能放 combined image sampler。
- 阴影 pass 的 push constant（`DoodleShadowPassPushConstants`）只有 `localToWorld`；树叶的镂空阈值写死在 `Shaders/tree_leaf.frag` 里（0.5）。

## 问题

- 材质属性落进了 pass 契约里，正是拆分 pass 契约 / 材质契约时想避免的那种耦合：每加一个 pass 都要决定带不带基色；某个着色器想要 roughness / metallic / emissive / alphaCutoff，没有任何地方能放。
- 树叶的阴影需要和前向一致的镂空（贴图 alpha + 阈值），但阴影 pass 拿不到基色，阈值也只能在各个着色器里各自写死。
- 每帧每个绘制项三次 `pow`，算的是加载之后就不会再变的值。

## 建议

- set 1 允许一个材质 UBO（例如约定 binding 0 是 uniform block）：成员布局用 SPIRV-Reflect 反射出来，材质文件按成员名填值（`"params": { "baseColor": [...], "alphaCutoff": 0.5 }`）。这和现在贴图按变量名配是同一套思路，不在描述文件里手写布局。
- 描述符管理器给每个材质建一份（或者从一块大缓冲里切一段），加载时写一次；sRGB → 线性在写入时做一次。
- push constant 只留逐绘制项的数据（`localToWorld`，以后可能是对象索引），前向和阴影的 push 契约因此同形。

## 解决标志

基色不再在 `DoodleForwardPassPushConstants` 里；着色器新增一个材质数值参数，只需要改 GLSL 和材质文件。
