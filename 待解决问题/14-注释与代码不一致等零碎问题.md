# 14 注释与代码不一致等零碎问题

类别：一致性 ｜ 优先级：低 ｜ 建议时机：随手

- `DoodleRenderPass::Destroy` 声明成 `virtual`，但类注释要求「派生类不要覆盖 Destroy」（派生类的清理走 `OnDestroy`）。去掉 `virtual`，或者标成 `final`，让编译器替注释把关。
- `DoodleRenderPipeline.h` 里 `m_pipelineWarmupQueue` 的注释说它「声明在所有资源成员之前……析构最晚」，实际排在深度图、描述符管理器、编译缓存之后。行为上没问题（队列不依赖其它成员），改注释或者挪位置二选一。
- `DoodleRenderPass` 类注释里生命周期那一段说「排在描述符管理器与驱动编译缓存之后建……原地重建时还要用到 set 0 布局」：set 0 布局是 pass 自己建的，`RebuildPipelines` 也不读它，这条理由已经过时；按实际依赖重写（原地重建要用到驱动编译缓存）。
- include 写法不统一：`DoodleShader.cpp` 写的是 `"../Vulkan/DoodlePipelineWarmupQueue.h"`，`DoodlePipelineWarmupQueue.cpp` 写的是 `"../Vulkan//DoodlePipelineWarmupQueue.h"`（多一个斜杠，而且是同目录的文件）；其它文件都写 `"Vulkan/..."`，同目录的直接写文件名。
- `DoodleVulkanConfig.h` 用了 `uint32_t`，却没有 include `<cstdint>`，现在是靠包含顺序碰巧编得过。
- 网格的顶点格式（`DoodleMesh::GetVertexFormat`）和材质着色器声明的顶点格式（`*.shader.json` 的 `vertexFormat`）之间没有核对。现在只有一种格式，不会出错；加第二种格式时，在材质挂到渲染器上（或者收集绘制项）时核对一次。
