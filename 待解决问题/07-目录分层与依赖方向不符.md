# 07 目录分层与实际依赖方向不符

类别：结构 ｜ 优先级：低 ｜ 建议时机：大改做完后的平静期

## 现状

- `Engine/Runtime/Vulkan/` 里混着两层东西：后端原语（Device、SwapChain、CommandManager、SyncObjects、GraphicsBuffer、Image、ShaderModule、PipelineObject、PipelineCompileCache）和渲染框架（RenderManager、RenderPipeline、RenderPass、ForwardPass、ShadowPass、DescriptorManager、PipelineWarmupQueue）。
- `Engine/Runtime/Rendering/` 里混着场景组件（Camera、Light、MeshRenderer）、GPU 资产（Mesh、Texture、Shader、Material）和帧 / pass 契约（PassShaderInterface、ForwardPassData、FrameContext、DrawItem）。
- 两个目录互相 include。例如 `Vulkan/DoodleForwardPass.cpp` 包含 `Rendering/DoodleCamera.h`、`DoodleLight.h`、`DoodleMesh.h`，`Vulkan/DoodleVulkanManager.h` 包含 `Rendering/DoodleFrameContext.h`；反过来 `Rendering/DoodleTexture.cpp` 包含 `Vulkan/DoodleCommandManager.h`，`Rendering/DoodleShader.cpp` 包含 `Vulkan/DoodlePipelineWarmupQueue.h`。

## 问题

目录名暗示的是「Rendering 与图形 API 无关、Vulkan 是后端」这样的分层，实际依赖却是双向的。「谁可以依赖谁」从目录上看不出来，新代码放哪儿全凭感觉；以后想把后端原语抽成接口，或者给 pass 写单测，都得先把这一层理清。现在不影响功能。

## 建议

按依赖方向重排，例如：

- `RHI/Vulkan/`：后端原语，不依赖下面任何一层。`DoodleVulkanManager::BeginFrame` 改成返回一个后端自己的小结构（帧索引、图像索引、命令缓冲），帧上下文由渲染框架组装；
- `Renderer/`：RenderManager、RenderPipeline、各个 pass、DescriptorManager、帧上下文与 pass 契约，依赖 RHI 和资产；
- `Rendering/`（或改名 `RenderAssets/`）：Mesh、Texture、Shader、Material，只依赖 RHI。预热队列这种两边共用的邮箱放到资产层或单独的公共位置，资产就不必 include 渲染框架；
- 场景组件（Camera、Light、MeshRenderer）不依赖渲染框架。

这是纯移动文件 + 改 include，适合放在一次大改完成、没有并行分支的时候做，免得和其它分支大面积冲突。

## 解决标志

后端原语目录不 include 任何渲染框架 / 场景头文件；组件与资产不 include 渲染框架头文件。
